Data Governance

Процесс, который держит данные достоверными

Источник: программа стажировочной площадки 2026. Ведущий: Семёнов Евгений Анатольевич, заместитель начальника отдела, отдел управления данными, ГКУ ЦЦТ РТ.
Data Governance — процесс создания достоверных данных в масштабе организации и поддержания данных достоверными.

Почему это важно именно сейчас

Три слоя стали сложнее

  • Слой систем — сотни новых программ, которыми пользуются разные направления деятельности организации
  • Слой данных — данных стало больше, и больше людей их используют
  • Слой инфраструктуры — облачные технологии и интернет вещей кардинально изменили ИТ-архитектуру
  • Безопасность — обеспечение конфиденциальности и защищённости данных стало сложнее

Так концепцию описывает DAMA-DMBOK — свод знаний по управлению данными от международной некоммерческой ассоциации DAMA International. Вендор-независимый и накопивший опыт тысяч компаний, он описывает что нужно делать для эффективного управления данными, из каких областей состоит дисциплина и почему это важно.

Актуальная редакция DMBOK2 (2017) выделяет одиннадцать областей знаний. В центре — Data Governance: система решений, ролей и правил, которая направляет и контролирует все остальные области.

Правила документирования наборов данных

Четыре ключевых правила

Согласно концепции Data Governance (корпоративного управления данными), документирование наборов данных превращает разрозненную информацию в прозрачный, надёжный и управляемый ресурс.

Оно строится на единых стандартах фиксации метаданных, закреплении ролей и описании жизненного цикла.

1

Ролевая модель

  • Data Owner — бизнес-руководитель: содержание набора, правила использования, ценность
  • Data Steward — описывает набор, контролирует качество, наполняет бизнес-глоссарий, разбирает ошибки
  • Data Custodian — ИТ: физическое хранение, резервные копии, права доступа, интеграции
2

Обязательный состав метаданных

  • Бизнес-контекст: процессы, термины, ссылка на бизнес-глоссарий
  • Технические атрибуты: источник, схема, поля, типы данных, стандарты именования
  • Data Lineage: откуда данные приходят, какие трансформации проходят, куда попадают
  • Правила качества: диапазоны значений, проверки на дубли и пропуски
  • Конфиденциальность: классификация (открытые, внутренние, ПДн, КТ) и правила доступа
3

Регистрация в каталоге данных

  • Вся документация — в единой системе: Collibra, Alation, DataHub, отечественный Arenadata Catalog
  • «Теневые» незадокументированные таблицы для промышленного использования запрещены
4

Актуализация и жизненный цикл

  • Документация обновляется одновременно со схемой данных (CI/CD, автоматический сбор метаданных)
  • Жизненный цикл набора: создание → хранение → архивация или удаление по регламенту

Зачем нужен SQL

  • изменять данные

  • выполнять вычисления
  • обеспечивать защиту данных

SQL · фильтрация

WHERE — какие строки оставить

SELECT * FROM AvgPricePVL WHERE "week" = 33;
SELECT * FROM AvgPricePVL WHERE "week" BETWEEN 33 AND 34;
SELECT * FROM AvgPricePVL WHERE "week" IN (31, 32, 33);
SELECT * FROM AvgPricePVL WHERE "title" LIKE 'Мука пшеничная кг';
SELECT * FROM "Ср цена по РТ" WHERE "Ср. цена по РТ" IS NULL;
SELECT * FROM AvgPricePVL WHERE "title" = 'Мука пшеничная кг' AND "week" = 33;

Условия: равенство, неравенство, диапазон BETWEEN, список IN, шаблон LIKE, пустое значение IS NULL; комбинации через AND и OR.

SQL · группировка

GROUP BY, HAVING, ORDER BY, LIMIT

SELECT DISTINCT("title"), AVG("Республика Татарстан") AS "Респ. Татарстан"
  FROM AvgPricePVL
  GROUP BY "title"
  HAVING AVG("Республика Татарстан") > 100
  ORDER BY "title" DESC
  LIMIT 5;

WHERE отсекает строки до группировки, HAVING — группы после и может содержать агрегатные функции. ORDER BY сортирует, DESC — наоборот, LIMIT оставляет первые N строк.

BETWEEN и IN

-- диапазон: expression [NOT] BETWEEN begin AND end

-- список: expression [NOT] IN (expression, ...)

ОператорКак формирует результат
INNER JOINКаждая строка левой таблицы сопоставляется с каждой строкой правой; при истинном условии строки склеиваются в результирующую таблицу
LEFT JOINСначала INNER JOIN, затем добавляются записи левой таблицы, не вошедшие в соединение; им соответствуют NULL из правой. Порядок таблиц важен
RIGHT JOINСначала INNER JOIN, затем добавляются записи правой таблицы, не вошедшие в соединение; им соответствуют NULL из левой. Порядок таблиц важен
FULL JOINСочетание INNER + LEFT + RIGHT: внутреннее соединение плюс незадействованные записи обеих сторон с NULL. Порядок таблиц не важен — оператор симметричен
